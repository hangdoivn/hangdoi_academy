# Appendix I — Capstone Rules Draft

## 1. Purpose

The Capstone is the final integrated evidence that a learner can move through a commercial Media workflow from brief to delivery at the intended entry level.

It is not an employment trial and must not be represented as guaranteed client work.

## 2. Capstone model

Core flow:

`Brief → Research → Pre-production → Production → Post → QC → Delivery → Review`

Possible categories:

- F&B;
- product;
- hospitality;
- people/lifestyle;
- short-form commercial;
- combined Photo/Video;
- approved simulated commercial brief.

## 3. Individual vs team work

Capstone may be:

- individual;
- team-based with individually assessed roles;
- mixed.

Where team-based, each learner must have identifiable evidence of their own contribution.

## 4. Approved brief

Each capstone brief should state:

- objective;
- target audience;
- deliverables;
- format/spec;
- deadline;
- available resources;
- constraints;
- brand/reference direction;
- role allocation;
- IP/confidentiality status;
- portfolio permission.

## 5. Pre-production evidence

Required as applicable:

- brief interpretation;
- research;
- references;
- moodboard;
- shot list;
- production plan;
- equipment list;
- schedule;
- role allocation;
- risk/safety check.

## 6. Production evidence

Record:

- learner role;
- assigned tasks;
- supervision;
- technical output;
- production behaviour;
- issues encountered;
- problem solving.

## 7. Post-production evidence

As applicable:

- selects;
- project/file structure;
- edit/retouch;
- sound;
- colour;
- graphics;
- versioning;
- QC;
- delivery.

## 8. Assessment domains

At minimum:

| Domain | Evidence |
| --- | --- |
| Brief interpretation | pre-production pack |
| Visual judgement | references + output |
| Technical execution | produced media |
| Workflow/data | files/backups/delivery |
| Post-production | finished output |
| Problem solving | issue log / assessor observation |
| Production behaviour | supervisor evidence |
| QC/delivery | final deliverables |

## 9. Hard gates

Capstone cannot pass with unresolved:

- material safety breach;
- data-integrity failure;
- serious conduct issue;
- plagiarism/fraud;
- unauthorized use/disclosure of protected client material.

## 10. Real-client capstone

If a real client/project is involved, require:

- client/operator approval;
- learner role definition;
- production-exposure terms;
- IP/use basis;
- confidentiality;
- privacy/releases;
- portfolio permission;
- remuneration review where direct productive work/output is used commercially.

A client project should not be chosen only to obtain free labour.

## 11. Simulated capstone

Where legal/operational conditions make client participation inappropriate, a simulated brief may be used.

A simulated brief should still contain realistic:

- client objective;
- constraints;
- deliverable spec;
- timing;
- revision/QC requirements.

## 12. Revision / rework

Possible process:

1. initial submission;
2. assessor records failed standards;
3. learner receives bounded feedback;
4. learner reworks defined items;
5. resubmission;
6. assessor records final result.

## 13. Originality / AI / third-party assets

Final program policy must state:

- permitted AI use;
- required disclosure;
- stock/template use;
- music/licensing;
- third-party footage;
- plagiarism rule.

Draft rule:

Any material contribution from AI, templates, stock or another person should be disclosed where relevant to assessment integrity.

## 14. Portfolio use

Capstone material may enter learner portfolio only if:

- rights allow;
- client/subject permissions allow;
- embargo has ended;
- confidentiality permits;
- attribution/credit requirements are followed.

## 15. Delivery archive

- approved brief;
- assessment sheet;
- learner evidence;
- final deliverables;
- revision history where material;
- permission/IP record;
